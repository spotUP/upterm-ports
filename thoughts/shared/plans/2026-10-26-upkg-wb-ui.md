# upkg Workbench window

## Goal
Owner idea: when `upkg` (or an UP-Term launcher) is started from Workbench (WBStartup message, argc == 0, no CLI)
it opens a native AmigaOS window: package list (installed / available / upgradable), Install, Remove, Upgrade
buttons, progress and log output. Today the only front end is the text UI (`pkgs/upkg-ui/src/ui.c`, `upkg browse`
inside a shell window).

## Findings
1. upkg-ui is NOT a GUI toolkit. libupkgui = ncursesw widgets + chrome (pkgs/upkg-ui/recipe.mk:1-5, `upkg-ui_DEPS := ixcompat ncurses`
   at :11). Nothing in it opens Intuition. So "upkgui" is not an option for D1.
2. `upkg browse` runs INSIDE the opkg process, no pipe, no child: patch pkgs/opkg/patches/0025-upkg-browse-runs-in-the-upkg-process-over-libupkgui.patch.
   Rows come from `upkg_browse_list(which)` (0025: ~line 89, in libopkg/opkg_cmd.c, open_memstream over `upkg_list_find` /
   `upkg_list_installed` / `opkg_solver_list_upgradable`; which = 0 all, 1 installed, 2 upgradable, 3 new) and are turned into
   rows "installed V / upgrade X to Y / available V / new V" by libopkg/upkg_browse.c (0025: ~lines 358-440). That parser is the
   single source of the row model today but is welded to the ncurses screen. Install/remove/upgrade run through `opkg_cmd_exec`
   (0025: ~line 566-650, rebuild of the hash after each).
3. Build: upkg-ui via tools/m68k-cc (gcc, ixemul), `__stack` + $STACK 262144 (recipe.mk:12-13); opkg is a CMake package on
   mk/amiga-ixemul.cmake, STACK 262144, STACK_VAR 1 (pkgs/opkg/recipe.mk:79-80), deps `ixcompat zlib bzip2 xz libarchive upkg-ui ncurses` (:66).
4. No Intuition GUI exists in upterm-ports. In vtcon, amarchy/gui.c:935-947 (OpenWindowTagList on a locked public screen, raw
   Intuition, no GadTools) and amarchy/win.c:148 (LockPubScreen "Workbench"); amarchy is vbcc/NDK-style C, not ixemul. Greps for
   CreateGadget, GadToolsBase, classact, listbrowser, ReAction in both repos: no hits. Reuse = the OpenWindow/IDCMP loop pattern
   and the WBStartup launch helper (vtcon/amarchy/wblaunch.c) only.
5. WBStartup: ixemul hands it through: argc = 0 and argv is the WBStartup message (ixemul-vtcon/library/_main.c:363-364;
   message taken from the process port at ix_startup.c:78). No UP-Term program tests argc == 0 today (grep in opkg patches,
   upkg-ui, amarchy, vtcon/src: only amarchy's own launching of WBStartup, wblaunch.c).
6. Progress lines: opkg prints through upkg_wrap and now flushes per line when stdout is a pipe (patch 0024, libopkg/upkg_wrap.c:198-203,
   src/opkg.c). Child processes (curl) are vfork+exec with IXSTACK (patch 0014). In-process commands write to stdout/stderr FILE*,
   which a GUI can redirect (see D4). ixemul has pipes and FIONREAD on a pipe (vtcon/RULES.md:65: ixfionread); select on a pipe fd
   under ixemul is UNVERIFIED (not found; R0 measures it).
7. The A1200 runs AmigaOS 3.2 (vtcon/RULES.md:18): GadTools (V37+) and ReAction (3.2 ships the classes; listbrowser.gadget, layout.gadget) both exist there.

## Architecture
- opkg stays the engine (in-process hash, `opkg_cmd_exec`). Two front ends over one core.
- NEW module `libopkg/upkg_rows.c/.h` (extracted from the row logic in upkg_browse.c, patch 0025 ~394-440): `upkg_rows_load(rows*)`
  builds the array {name, status kind, installed version, available version, description} from `upkg_browse_list(0..3)`;
  `upkg_rows_run(cmd, name, sink)` runs install/remove/upgrade through `opkg_cmd_exec` and rebuilds. Pure C, no curses, no Intuition,
  host-testable. upkg_browse.c (text) and the new `upkg_wb.c` (window) both consume it. No second parser.
- NEW `libopkg/upkg_wb.c/.h`: Intuition window, `int upkg_wb(struct WBStartup *)`; compiled only for Amiga builds.

## Decisions for the owner
- D1 toolkit. (a) GadTools, recommended: V37, opens on every OS the kit supports, listview + buttons + text gadget are enough, no
  new SDK dependency beyond NDK headers. (b) ReAction: nicer listbrowser/layout but OS 3.5+ only, ixemul/gcc headers for the classes
  must be vendored, much more code to link and test. (c) "upkgui": ruled out, it is ncurses (Finding 1).
  The A1200 (3.2) runs either; stock 3.1 machines only (a).
  DECIDED (owner, 2026-10-26 05:45): (a) GadTools, V37.
- D2 entry. (a) Same binary, recommended: `main` sees argc == 0, calls `upkg_wb`; one install, one stack setting, icon points at
  upkg (needs `upkg.info` with TOOLTYPES, stack 262144 in the icon too). Trade-off: opkg.c main gains one early branch.
  (b) Separate `upkg-wb` program with its own icon: cleaner main, but a second binary linking libopkg (or a second process with
  the pipe problem) and a second recipe, check and stack.
  DECIDED (owner, 2026-10-26 05:45): (a) same upkg binary, argc == 0 branch.
- D3 scope of v1. (a) Recommended: list (All / Installed / Upgradable tabs or cycle gadget) + Install + Remove + Upgrade +
  Update feeds button + progress; (b) minimal: list + install + remove + log, no upgrade/update/feed choice. Feed selection
  (choosing sources) is left out of v1 in both: no CLI equivalent in browse today.
- D4 log. (a) Text gadget (multi-line read-only GadTools TEXT/ string or custom-drawn lines) in the window, recommended:
  one window, no extra process, needs stdout redirected to a pipe or memstream that the event loop drains (R0); (b) separate CON:
  window: trivial (`Open("CON:...")`, dup2 onto fd 1/2, no pipe reading), but a second window to place and close, and ixemul
  stdio on a CON handle must be tested; fallback if R0 shows select/FIONREAD on pipes is unreliable.

## Implementation items
- R0 spike (measure first): in the real binary, redirect fd 1/2 to a pipe, read with FIONREAD/WaitSelect in the Intuition loop; record
  that a line printed in a vfork child (curl) arrives live. Files: scratch test under pkgs/opkg/check/. Proves D4 choice.
- H1 extract rows module: `libopkg/upkg_rows.c/.h`, new patch 0028 (+ patches/ series). Test: host test over fixture list text for
  all four kinds, run by the host build (like test_chrome.c). `upkg browse` rewired to it; existing browse rig check still passes.
- H2 `argc == 0` branch in src/opkg.c main (patch 0029): calls `upkg_wb` when argv is a WBStartup, else unchanged. Test: host
  build stubs `upkg_wb`, asserts it ran (sentinel) only with argc == 0.
- G1 window skeleton: open on the Workbench public screen (LockPubScreen "Workbench", as amarchy/win.c:148), GadTools gadgets: listview,
  cycle (All/Installed/Upgradable), Install, Remove, Upgrade, Update, log gadget, Quit; IDCMP loop with GT_GetIMsg; clean close, UnlockPubScreen,
  reply WBStartup last. Files: libopkg/upkg_wb.c, CMakeLists (Amiga only), recipe.mk deps.
- G2 list fill from upkg_rows_load, selection enables buttons by kind (installed -> Remove/Upgrade only if upgradable; available -> Install).
- G3 actions: run through upkg_rows_run on a worker (a Task or a child process, decided by R0; the window must not freeze: Intuition loop keeps
  running, buttons disabled during a run, window close refused with a requester while running), progress to log gadget.
- G4 package install questions: a package with install questions of its own runs in the text UI in browse (0025 ~583); in the window: show a
  requester and run it in a CON: window or refuse in v1 (the owner is told in the plan result; default refuse with a message).
- R1 reachability test (rig, `--os 32 --max`): `tools/rig` script in vtcon starts from Workbench via wasabi (double-click the upkg icon),
  asserts a sentinel line the window writes to a file (`UP-Term:log/upkg-wb.log`: "window opened, N rows") and a post-install state
  (package present in status file) after a scripted click on Install through amiga_ui_click; the stock `upkg list` path is checked
  unchanged. Stack: checks `__stack` and the icon stack.
- D1doc docs: upkg man/README text, RULES.md row for the rig command, thoughts handoff.

## Risks
- Stack: icon stack must be >= 262144 (Workbench ignores `__stack` cookie for icon starts? ixemul honours $STACK/`__stack` in ix_startup, UNVERIFIED for WBStartup
  starts: R1 checks the actual stack with the stack-check helper); GadTools code is light, opkg + libarchive is the load.
- ixemul WBStartup: message must be replied exactly once after the window is closed; amarchy's own WBStartup launch keeps its reply port (leaf.h:70), so the
  reply must not happen from a deleted port; test on exit.
- Screen: Workbench public screen is the default (matches the launcher use); UP-Term's own screen is not assumed. vtcon's own front screen
  (`lock_front_screen`, gui.c:1111) is not used here.
- A Workbench start has no stdout: any `printf` in opkg paths goes to nowhere or a console window ixemul may open (default CON: window); H2/G3 must
  point fd 0/1/2 explicitly before any command runs.
- Network: curl children need IXSTACK (patch 0014); a GUI start must still set it (the code sits in main, verify the branch is after it).
